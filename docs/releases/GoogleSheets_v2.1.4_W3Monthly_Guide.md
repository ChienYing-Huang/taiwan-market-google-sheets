# StockMarketGoogleSheets v2.1.4 — W3 改由當月月選承接

本版延續 v2.1.3 的每日更新、歷史區間修復、50 點價平履約價與 IV 計算，
只修正「週選擇權 W」的契約選擇策略。

## 正確的週三到期序列

週選擇權 W 區塊不再只從 W1 / W2 / W4 / W5 中挑選，
而是改成「最近一個尚未到期的週三到期序列」：

W1 → W2 → 當月月選 → W4 → W5

原因：
- 期交所沒有 W3。
- 每月第三個星期三是月選契約的最後交易日。
- 因此第三週的 W 位置應由當月月選 YYYYMM 契約承接。

## 到期日當天的規則

沿用 v2.1.2：

只有「契約到期日 > 資料日期」的契約可以使用。

也就是：
- 到期日前：使用該契約。
- 到期日當天：直接切換下一個週三到期序列。

## 範例：2026 年 8 月

概念上：

- W1 到期前 → 202608W1
- W1 到期當天起 → 202608W2
- W2 到期當天起 → 202608（月選，第三週）
- 202608 月選到期當天起 → 202608W4
- W4 到期當天起 → 若有 W5 則 W5，否則下一個月的 W1

因此：
- 2026-08-13 ～ 2026-08-18：W 區塊應使用 202608 月選資料。
- 2026-08-19 是第三個星期三，也是 202608 月選到期日；
  當日依規則不再使用 202608，因此 W 區塊改用下一個週三序列 202608W4。
- 月選區塊在 2026-08-19 當日則會切到下一個月選契約。

## 對 OI / IV 的影響

同一個 `weeklyWednesday` 契約物件同時提供：
- 週選擇權 W (OI)
- 週選擇權 W (IV)

所以第三週期間，W(OI) 與 W(IV) 都會從當月月選契約取得資料，
不會出現 OI 用月選、IV 卻用 W4 的不一致情況。

月選區塊仍獨立存在，因此第三週期間：
- W 區塊
- 月選區塊

可能同時顯示同一個 YYYYMM 月選契約。這是刻意設計，因為該月選同時承接第三週週三到期的位置。

## 歷史修復

v2.1.3 的「重新抓取歷史區間」也共用相同的契約挑選函式，
因此歷史資料重新修復時會自動套用本版 W3 = 當月月選的規則。

## 升級方式

1. Google Sheets → 擴充功能 → Apps Script
2. 將目前 Code.gs 替換成 `StockMarketGoogleSheets_v2.1.4_W3Monthly.gs`
3. 儲存
4. 執行 `updateMarketData()`

如果過去第三週資料曾被錯誤抓成 W4，
可再使用：

`台股行情工具 → 重新抓取歷史區間`

重新修正受影響的日期。
